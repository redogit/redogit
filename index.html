I use Git the way its history wants to be used: keep what actually happened, find the difference that matters, build a smaller successor, check it, and keep going.

REDOGIT: a redo is not a rewritten past. It is a verified successor with provenance.

The REDOGIT loop

Enough structure to improve a project without carrying every old assumption forward.

  1. Load
    Start from the actual code, artifact, idea, or failure.
  2. Bound
    Decide what the project is responsible for and what it is not.
  3. Redo
    Change the smallest consequential thing rather than rebuilding accidental complexity.
  4. Check
    Make the result observable, retain the lineage, then continue.
