## 1. Start with the highest purpose

The governing root is the existing Cooperative Implementation Protocol:

> THE SYSTEM SERVES HUMAN LIFE. HUMAN LIFE DOES NOT SERVE THE SYSTEM.

The practical aim is to help people understand, preserve, question, create, cooperate, recover, and act while protecting agency, accessibility, privacy, evidence, and the ability to change course.

The organizational lens remains:

`higher organization = differentiation + relation + coordination`

“Highest view” means the widest justified view needed to understand the human obligation, affected workstreams, dependencies, consequences, and recovery routes **before** selecting a local action. It does not mean maximum abstraction, maximum simultaneous edits, an unlimited search, or one central authority over all projects.

`Object identity is invariant; coordinates are negotiable.`

This is a declared carrier obligation, not a claim that every transformation preserves every property. A transformation that fails its declared reconstruction check remains a mutation, loss, or unresolved transport—not an admitted rotation.

## 6. Adaptively organize only after orientation

Use three comparisons before changing anything:

- **Up/down:** human obligation -> project responsibility -> interface -> smallest failing structure; return upward to assess the whole consequence.
- **Side to side:** compare peer workstreams, shared dependencies, privacy boundaries, claims, and active edits. Relatedness is not permission to cross-write.
- **Forward/back:** expected outcome -> observed result -> residual; predecessor -> candidate -> reconstruction -> Way Back.

Selection is constrained rather than globally scored. First reject unauthorized, privacy-violating, unbounded, or unreconstructible actions. Among the remaining actions, preserve the agreed portfolio order unless a documented dependency or protection obligation requires a bounded exception. Record the exception and its reason. Prefer the smallest action that resolves a consequential distinction or unblocks the next legitimate obligation.

For every selected action, carry:

```text
Subject / human usefulness witness
Target-local authority and exact source revision
Expected outcome / observed outcome / consequential residual
Declared invariants / permitted loss / dependencies
Smallest proposed change / independent counterprobe
Decision: accept | reject | defer
Evidence / claim ceiling / privacy gate / Way Back / Remainder
```

Carrier transport remains:

`Resolve identity -> encode for target Surface -> transport -> decode/reconstruct -> compare invariants -> record residual/provenance`

Generation, verification, admission, merging, release, and publication are separate decisions. A green check at an earlier head cannot certify a later head. An expected-head SHA is required for a subsequent authorized merge; any moved head or conflicting base causes re-observation, not a force update.

## 7. Concurrency and completion rules

One logical repair should have one active target-local write path. Parallel work belongs on complementary routes or isolated proposals. A moving branch is a signal to coordinate; it is not a reason to race another contributor with speculative edits.

A scoped alignment pass is complete only when the current purpose, authority, dependencies, observed results, retained failures, and next handoffs are reconstructible. A project is complete only against its own declared acceptance condition.

`DELTA_ZERO -> NO_CHANGE`

If no justified consequential difference remains, retain the state and stop. Do not create commits just to demonstrate activity, invent a missing task, erase failure history, or relabel deferred/open research as finished.

The present Remainder is explicit: native evidence for several portfolio gates still needs target-local revalidation; this draft is not accepted project governance; open PRs can move; local/device parity is not established by this document; and public synchronization remains separately gated.
