# Algorithmic Condensed Wisdom Analysis — 2026-09-25

> **CURRENT SYNTHESIS, NOT RETROACTIVE NAMING.** The behavior recovered here existed across earlier reconstruction, language/distinction, Book-of-Books, and child↔elder work. I am giving the combined mechanism one current Surface now. I am not claiming every earlier artifact used this exact name or wording.

## 0. TERMS FIRST

### WISDOM
**MEAN:** a rule / relation / warning / method earned through consequences, comparison, correction, and reuse.  
**NOT:** age, confidence, popularity, repetition, or a sentence that sounds right.

### CONDENSED WISDOM
**MEAN:** wisdom compressed to a small operational carrier **without losing the way back to what earned it**.  
**KEEP:** exceptions, conditions, consequence, uncertainty, provenance, evidence, failure, cost, and remainder when they can change use.

### RULE
**MEAN:** the compressed operational statement I can try to apply.  
**NOT:** authority by itself.

### EXPERIENCE
**MEAN:** observations + actions + consequences + failures + repairs + context.  
**NOT:** automatically general evidence outside the conditions where it happened.

### HOMEWARD
**MEAN:** the reverse path from the compressed rule to the observations / distinctions / evidence / obligations that earned it.

### KNOWLEDGE DECAY
**MEAN:** I can still repeat the words but can no longer reconstruct a consequential distinction needed to know when / why / whether the rule applies.

## 1. THE DOUGHNUT SPLIT

```text
MAKING THE DOUGHNUTS
!=
KNOWING HOW TO MAKE THE DOUGHNUTS
!=
KNOWING WHY THIS RECIPE WORKED HERE
!=
KNOWING WHEN NOT TO USE IT
```

The doughnut is a Result.

The recipe is a Method carrier.

The know-how includes timing, conditions, failure recognition, repair, and judgment.

The wisdom is what survives enough comparison to become reusable **without deleting the reasons it deserves reuse**.

```text
RESULT != METHOD
METHOD != PROOF
PROOF != EXPLANATION
EXPLANATION != RECONSTRUCTION
RECONSTRUCTION != SOURCE
```

## 2. CHILD -> ELDER -> CHILD

The forward direction:

```text
CURIOSITY
-> OBSERVATION
-> IMITATION
-> PLAY
-> ERROR
-> CONSEQUENCE
-> MEMORY
-> REPETITION
-> COMPARISON
-> STUDY
-> ABSTRACTION
-> TESTING
-> RESPONSIBILITY
-> TEACHING
-> LOSS
-> REVISION
-> COMPRESSION
-> PRACTICAL WISDOM
```

The reverse direction matters just as much:

```text
WISDOM
-> RULE
-> CONDITIONS
-> EXCEPTIONS
-> ASSUMPTIONS
-> EVIDENCE
-> EXPERIENCE
-> OBJECT
-> QUESTION
```

If I can only go forward, I have compression.

If I can go both ways, I have a chance at **reconstructible wisdom**.

## 3. ALGORITHMIC CONDENSATION

The analysis loop I want is:

```text
PRESERVE
-> DECOMPOSE
-> FIND CONSEQUENTIAL DISTINCTIONS
-> ONE-DEGREE VARY
-> TEST
-> RECORD FAILURE + CONSEQUENCE
-> COMPARE
-> TEST INTERACTIONS
-> IDENTIFY WHAT SURVIVED
-> ADMIT ONLY THE BOUNDED RULE EARNED
-> COMPRESS
-> REVERSE-DECOMPOSE
-> REUSE ONLY WHERE CONDITIONS STILL FIT
-> RECURSE
```

A shorter carrier:

```text
OBSERVE
-> FAIL / REPAIR
-> COMPARE
-> KEEP WHAT SURVIVED
-> COMPRESS
-> PROVE I CAN UNFOLD IT
-> REUSE
```

## 4. COMPRESSION GATE

Before I call a short rule reusable condensed wisdom, I should be able to recover:

```text
OBJECT?
OBLIGATION?
SOURCE?
WHAT HAPPENED?
WHAT FAILED?
WHAT CHANGED?
WHAT SURVIVED?
CONDITIONS?
EXCEPTIONS?
COUNTEREXAMPLE?
EVIDENCE?
COST?
HOMEWARD?
CLAIM CEILING?
REMAINDER?
```

If the short form cannot point back to those when they matter, the compression is too destructive.

## 5. WHAT GETS COMPRESSED

Compress repeated structure, not consequential uncertainty.

Good compression targets:

```text
repeated relation
repeated repair
repeated failure signature
stable precondition
stable stop condition
stable transformation
stable reconstruction receipt
```

Do not silently compress away:

```text
exception
scope
counterexample
authority
provenance
negative result
cost
unresolved remainder
affected obligation
```

## 6. KNOWLEDGE DECAY DIRECTION

I do not want to wait until a carrier is broken and then ask whether knowledge decayed.

The carrier should move away from decay while it is being transformed.

Working rule:

```text
OBJECT / OBLIGATION STAYS
CARRIER MAY MOVE
MOVE TOWARD GREATER RECOVERABILITY
MOVE AWAY FROM IRREVERSIBLE LOSS
```

A shorter rule is better only when it is still faithful enough for the obligation.

```text
SMALLER != BETTER
SMALLER + RECONSTRUCTIBLE + SUFFICIENT = CANDIDATE BETTER CARRIER
```

## 7. FAILURE MODES

### SLOGANIZATION
The rule survives; the reasons disappear.

### EXCEPTION ERASURE
The average case becomes a fake universal.

### EVIDENCE LAUNDERING
Repeated retelling begins to look like independent support.

### RECIPE WORSHIP
A procedure keeps running after its obligation or context changed.

### SUCCESS AMNESIA
The result is preserved but the method / provenance / conditions are lost.

### FAILURE AMNESIA
Only successful paths are kept, so future search repeats old mistakes.

### IRREVERSIBLE COMPRESSION
The carrier gets smaller by deleting the route Homeward.

## 9. EXAMPLE — THE CURRENT P VS NP NORMALIZATION WISDOM

The current long proof work compresses to:

```text
DON'T BRANCH ON A DEGREE
UNTIL I HAVE FAILED TO PROVE THAT THE DEGREE IS:

    REDUNDANT,
    DOMINATED,
    FUNCTIONALLY DETERMINED,
    LOCALLY SATISFIED,
    OR CHEAPLY PROJECTABLE.
```

That sentence is useful only because I can unfold it back into the exact normalization rules, guards, proof receipts, lifecycle cost, and residual that earned it.

That is the distinction:

```text
THE RULE IS THE CARRIER.
THE PROOF / TRACE / CONDITIONS ARE WHY I AM ALLOWED TO TRUST THE CARRIER.
```

## 10. CLAIM CEILING

This is a current research / engineering method for preserving and compressing reusable operational knowledge.

It is **not** a theorem that:
- every useful form of human wisdom is algorithmically extractable;
- the compression is unique or optimal;
- a reconstructed rule preserves every human meaning;
- repeated usefulness proves universal validity.

The active obligation is smaller and more practical:

```text
WHEN I COMPRESS A LEARNED RULE,
KEEP ENOUGH OF WHY IT WORKED
THAT I CAN QUESTION IT,
RECONSTRUCT IT,
REPAIR IT,
AND KNOW WHEN NOT TO USE IT.
```
