## 3. The fighting point

The exact phrase **fighting point** was not found in the indexed Git text searched on 2026-09-19. It is therefore recorded here as a **current successor name** for an older rule, not retroactively presented as an old Git quote.

Define:

```text
FIGHTING_POINT(x, y, O)
```

as the boundary where two states can no longer be safely collapsed under obligation `O`.

The historical Decision Field formulation already states:

```text
x ~_O y

iff

no admitted consequential test currently distinguishes
x and y for obligation O
```

A witness that changes a protected consequence earns a distinction:

```text
w(x,O) != w(y,O)
    =>
x !~_O y
```

The fighting point is therefore the **preserve-the-difference boundary**.

## 31. Pairity before parity

**Pairity** preserves the two sides and their relation before asking whether they match.

```text
PAIRITY
= keep participant A
+ keep participant B
+ keep A->B
+ keep B->A
+ keep each relation
+ preserve mismatch
```

Then:

```text
PAIRITY
-> COMPARE
-> SAME WHERE EXPECTED
-> DIFFERENT WHERE REQUIRED
-> PARITY ONLY WHEN JUSTIFIED
```

This strengthens the existing Fighting Point / obligation-relative equivalence rule:

```text
PAIRITY != FORCED_EQUALITY
AGREEMENT != COLLAPSE
```
