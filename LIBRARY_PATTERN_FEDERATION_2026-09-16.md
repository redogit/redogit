# REDOGIT Library Pattern Federation — 2026-09-16

**Authority:** navigation/method only  
**Status:** additive, non-destructive federation overlay

This checkpoint aligns Library-like organization patterns across the connected REDOGIT repositories without merging project identity, evidence, ownership, or runtime authority.

## Canonical loop

`recover identity -> preserve source/provenance -> locate current authority -> retrieve narrowly -> type the relation -> inspect evidence -> test/admit locally -> retain failures/remainder -> add recovery handle -> recurse only when useful`

## Common record surface

A Library-like carrier should be able to expose or recover: identity, source identity, provenance, chronology, current authority, observer/task, relation type, evidence status, claim ceiling, transform history, failures/nulls/invalids, improvement coordinates, access/privacy/rights, unresolved remainder, and a recovery handle.

## Invariants

- identity before similarity
- source-native before synthesis
- historical authority != current authority
- related != supports
- retrieval != evidence
- observation != interpretation
- generation != certification
- promotion requires an explicit witness
- failures/nulls/invalids remain addressable
- cross-project relation != authority transfer
- viewpoint change != task change
- preserved != available != active

## Admission and privacy boundary

The federation may transfer method and navigation contracts. It does not silently transfer scientific support, truth, ownership, historical authority, runtime authority, private material, rights, or publication permission. Receiver-local verification remains mandatory for promoted claims.

Private Library contents and paths are not exported by this public binding. Historical/source-native material is not rewritten; corrections and current-state changes are represented as additive successor, supersession, or binding records.
