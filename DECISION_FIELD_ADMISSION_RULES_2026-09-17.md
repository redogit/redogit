# Decision Field Admission Rules — 2026-09-17

A project may adopt the shared Decision Field structure without surrendering its local evidence or domain laws.

## Required declaration

Every specialization must declare:

```text
X = possibilities / conditions
O = observer / task / obligation / goal context
D = consequential distinctions
R = typed relations
F = admitted functions/operators
E = evidence/provenance/uncertainty/claim ceiling
G = desired bounded result
U = unresolved remainder
```

## Operator admission

A candidate function is not automatically admitted because it is useful in another domain.

Promotion path:

```text
candidate
-> exact/task-local definition
-> preconditions
-> protected invariants
-> counterprobe
-> verifier/certificate
-> cost/resource accounting
-> failure semantics
-> reconstruction/lift if destructive
-> bounded admission
```

## Required anti-contamination checks

Before moving a function between projects ask:

1. Is the same distinction consequential in the target domain?
2. Is the relation type actually the same or merely analogous?
3. Does the transform preserve the target obligation?
4. Is the evidence independent or only inherited/repeated?
5. Does the source claim ceiling remain visible?
6. Can the connection be removed without rewriting either endpoint?

If any answer is unknown, keep the bridge `OPEN_POSSIBLE_CONNECTION` or `GENERATOR_ONLY`.

## Quantum boundary

Quantum measurement may instantiate the structural interface, but the physical laws are not imported from SAT/optimization/planning.

```text
SHARED_FIELD_STRUCTURE != SHARED_PHYSICAL_MECHANISM
QUANTUM_COLLAPSE != CLASSICAL_BOOLEAN_BRANCHING
```

## Open-math boundary

P-vs-NP and Hodge remain open. Decision Field provides method/representation machinery only until an independently valid proof closes the relevant mathematical obligation.
