This is the **active project slice** of the wider Libraries-of-Libraries navigation surface.

It answers one narrow question:

> Which already-existing projects are current enough to connect **right now** without promoting drafts, preserved history, unlisted material, or unsupported claims?

The answer is deliberately local and reversible.

```text
ACTIVE != UNIVERSALLY_VALID
CURRENT != AUTHORITATIVE_OUTSIDE_OWN_PROJECT
CONNECTED != MERGED
RELATION != EVIDENCE_TRANSFER
RUNNABLE != PRODUCTION_READY
PRODUCT_SUCCESS != SCIENTIFIC_VALIDATION
PLAY != EVIDENCE
OPEN_PR != ACTIVE_MAIN
```

## Activation rule

A project is connected here only when its inspected default-branch state is one of:

- explicitly active research;
- deployed/current infrastructure;
- current runnable local tooling;
- current public tool/game surface;
- current bounded publication or research aid.

A project is **not** promoted into the active slice merely because it exists, has an old PASS, appears in history, or has an open PR.

This is important because several current lines intentionally remain:

- preserved lineage;
- draft/review work;
- unlisted distribution;
- historical reconstruction;
- unresolved research.

Those states remain visible without being relabeled.

# What connection means

An active connection gives a user a path to the project.

It does **not**:

- change that project's owner or authority;
- import its claim status into another project;
- turn a local prototype into a production service;
- turn a game mechanic into science;
- turn a verified finite computation into an open-problem proof;
- activate another system merely by listing it.

The routing layer stays useful only if every project remains detachable.
